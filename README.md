# HYPERBENCH

**Computational frameworks for traversable hyperspace: topological manifolds, exotic energy models, and algorithmic control of higher-dimensional spacetime.**

Complete reproducibility artifact for the manuscript of the same name. Every numerical claim in the paper is produced by code in this repository and asserted by the test suite. The manuscript itself is rebuildable from source.

## What this is

A dependency-light framework (NumPy, SciPy, SymPy only) in which candidate spacetime geometries are treated as program objects: metrics are compiled from symbolic specifications, curvature and stress-energy are derived automatically, energy conditions are evaluated as machine-checkable predicates, exotic-matter budgets are posed as constrained optimisation problems, and throat stability is analysed as a feedback control problem.

**This is not a claim that traversable wormholes or warp drives are achievable.** It is a demonstration that the question admits rigorous computational treatment, and that such treatment yields bounds the analytic literature has not emphasised. See the manuscript's "Epistemic status" section (§1.2).

## Quick start

```bash
git clone https://github.com/<your-username>/hyperbench.git
cd hyperbench

pip install -r requirements.txt     # or: make install-locked  (exact pins)
python hyperbench/run_all.py        # ~81 s, single CPU core
python tests/test_paper_claims.py   # ~4 min, 15 assertions
```

Expected final line: `15/15 tests passed`.

Fully isolated alternative, pinned to the exact published environment:

```bash
make docker
```

No network access, no GPU, no proprietary data. There are no external datasets — every input is generated by the code here.

## Figures

Figure 1 (the pipeline diagram in §5.2 of the manuscript) is **generated from
code**, not stored as a hand-edited binary. `figures/make_architecture_figure.py`
draws it with matplotlib and emits PNG, PDF, and SVG. The PNG is embedded in the
Word file, so the diagram cannot be accidentally reflowed or re-edited as text —
and it stays part of the reproducible artifact:

```bash
pip install -r requirements-paper.txt
make figures
```

`make paper` regenerates the figure automatically when matplotlib is available,
and falls back to the committed PNG when it is not.

## Validation strategy

Every load-bearing number is computed twice by independent routes. Full table in `VERIFICATION.md`; in summary:

- Symbolic stress-energy checked against published Morris–Thorne expressions (exact symbolic match).
- Proposition 1 proved analytically **and** confirmed numerically across two metric families.
- The SLSQP optimiser is validated against a closed-form optimum before being trusted where no closed form exists.
- `V''(a₀)` computed both in closed form and by finite-differencing a numerically integrated ODE (agreement 3×10⁻⁶).
- The closed-form delay margin is verified by direct integration of the delay differential equation.

## Two numerical pitfalls documented here

Both were encountered during development and are recorded because they fail *silently*:

1. **SymPy assumption mismatch.** Symbols declared `real=True` and `positive=True` are distinct objects, so `expr.subs(r, b0)` silently no-ops if the caller's `r` differs from the constructor's. Radial coordinates are declared `positive` uniformly.
2. **Truncated semi-infinite integrals.** For shape functions decaying as `r^-α` with small α, the VIQ integrand's tail falls as `r^-(1+α)`; truncating at any finite radius discards ~`r_max^-α`, still ~1% at `r_max = 10⁴b₀` for α = 0.5. Adaptive quadrature on `[b₀, ∞)` is used instead.

An earlier version of Experiment B also returned values *below* a proven bound — the optimiser was correctly solving an under-specified problem in which asymptotic matching to flat space was not enforced. The analytic bound functioned as a test oracle. See `VERIFICATION.md` §6.
